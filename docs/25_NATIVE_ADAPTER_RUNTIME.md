# 原生适配运行边界

ProjectOrch通过官方CLI/RPC驱动已绑定原生会话，通过MCP提供角色工具。原生程序保持原样；会话、轮次、绑定代次与当前内核owner分开保存，不能用新建会话或日志改写冒充同一原轮恢复。

当前受管Codex默认只读，ZCode承担文件执行；仅使用已验证默认模型，严格模型/推理请求不支持时拒绝输入。所需程序由用户安装并正常登录，不读取或复制认证秘密。配置见 `user/ALPHA_FIRST_USE.md`，恢复边界见 `user/WINDOWS_CANDIDATE_GUIDE.md`。

支持摘要仅陈述历史上实际测试通过的版本及逐能力覆盖，不作为版本或历史程序哈希白名单。其他版本可使用现有适配器实现尝试运行，实际协议或接口失败如实报告，未测试的构建不冒称已测通过。权限、预算、暂停、单 owner 和原生会话身份仍校验；运行中程序更新后需正常重启重新加载。基本Alpha子集验收不扩展为全部规划能力已通过。

发送前固定目标、授权、预算和占位；官方started记录精确原生ID。CLI进程退出、执行期限到限、会话idle或工具完成都不能单独证明业务完成。unknown保留原事实并停止新输入，不自动重试。executionTimeoutMs为整轮执行期限，默认15分钟、上界30分钟；旧timeoutMs别名显式值保持，冲突拒绝。RPC请求独立20秒默认、60秒封顶。执行期限与项目授权窗口不同，不扩大次数/预算，更不核销旧未知结果。

任务原生执行attempt已running时，业务任务仍可能draft；执行角色必须按最新版本领取，再提问/登记/提交。工具调用传输completed不等于业务成功，问题须成功回执及真实questionId后才保存等待。独立复核应核对实际成果和测试，不依据执行者自报裁决。
