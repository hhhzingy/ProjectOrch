# 可复制给其他 AI 的指令

以下指令供用户明确选择后交给接手AI，不是软件自动授予权限。路径和模型以用户本次提供的信息为准，已有授权持续有效。先读根目录 AI_START_HERE.md 和 AI_INSTALL_AND_USE.md。

## 安装和零模型配置检查

```text
请安装并配置 ProjectOrch。安装位置、数据目录及官方Harness路径先从我提供的信息和本机有限目录发现获取；不要把示例路径当实际路径。
先读下载包的 AI_START_HERE.md 和 docs/user/AI_INSTALL_AND_USE.md。
Windows ZIP使用自带runtime/node.exe；源码先npm ci --ignore-scripts并构建。
依次运行 scripts/setup.mjs 的 discover、首次init、check --probe-native；已有native-config.json不得覆盖。若我已经允许复用同用户的Codex登录，init使用--share-codex-login；不读取auth.json、不索要API Key、不复制任何认证文件。ZCode复用官方已有登录，账户供应商与自定义API供应商分开，不擅自替我选模型。
正常启动内核后用check --probe-mcp核对控制连接。生成当前安装和数据目录的MCP片段，通过官方入口合并到我选用的控制Harness，保留其他设置；在真正的控制聊天调用projectorch_identity确认。不要把配置保存当已加载。
本轮只做零模型安装检查：不建团队、不创建原生会话、不发模型输入、不购买额度、不用reset credit。浏览器配对代码和本机控制凭据不写入报告。缺少无法发现的路径/偏好时只问必要信息。
最后报告实际安装版本、目录、各层检查结果、未验证的账号/模型权益和剩余步骤；不得把配置通过说成真实协作通过。
```

## 创建项目并委托负责人

```text
请使用已配置的ProjectOrch管理我的项目。项目目录、目标、Codex/ZCode模型供应商和预算沿用我已给出的授权，缺少时先补必要信息。
先在本控制聊天调用projectorch_identity和项目查询，避免重复建项目。新项目通过Web三角色模板明确配置职责/权限/并发/预算，使用页面生成的真实启动指令，不猜ID或工具参数。控制聊天不冒充受管负责人。
记录bootstrap的operationId，只查询原操作；全部ready后向负责人发送一次目标，使用稳定requestId。负责人按较大批次安排执行和独立复核，持久登记成果、问题和下一步。Codex按每个角色授权沙箱运行，不提高到完全可写。
普通步骤连续执行，遇需要用户决定的信息用指定问题入口。遇unknown或已约定停止条件，保留原会话/轮次和发送记录，不重发、不删锁、不新建替代会话。最终依据实际文件和测试汇报已完成、未完成与限制，不能只引用Agent自报。
```

## 重启后接手已有项目

```text
请接手已有ProjectOrch项目。使用原数据目录正常启动，通过MCP先读取项目/角色/任务/操作/消息状态，核对原绑定及会话ID，不重新创建团队。
正常终态按依赖继续；running/unknown先核对精确原轮及持久回执。没有可信终态时保持待核对，不凭idle/PID死亡宣布成功，不改SQLite、不删租约、不复制历史、不换requestId盲重发。保留用户暂停、权限和预算。先给我简短的当前状态与可安全继续项，再按既有授权推进。
```

## 经授权的小型真实验证

```text
请在我指定的独立测试项目执行已授权的小型真实验证，沿用指定模型/供应商和次数/时间预算，不扩大范围。
先通过静态检查和MCP身份检查；保存创建的原生会话、轮次、操作ID及实际文件。至少验证一次真实任务交接和结果复核，按本轮目标决定是否需要同ID重启续行。模型实际生效依据官方元数据核对，不依据模型自报。
unknown、429、原生失败或到限按约定停止，不自动重试、不改绑证据。报告本轮真正执行的范围与未验项；测试目录只清理本轮可重建产物，不删除用户资产和必要验收证据。
```
