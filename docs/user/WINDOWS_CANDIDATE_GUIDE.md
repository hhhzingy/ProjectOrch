# 本地运行、停止与恢复

源码运行见README；Windows候选ZIP应在新目录解压，以普通用户运行 `start.cmd --data-dir E:\ProjectOrchData --pair`。使用启动输出的实际地址和本次配对代码；不记录代码到报告。关闭前Ctrl+C，保留数据目录及项目目录；重新启动使用相同数据目录。升级前备份数据，不使用旧程序打开新schema库。

原生配置保持官方程序原样，使用支持的CLI/RPC或MCP入口。登录由官方程序自己完成，不读取/复制认证秘密。正常关闭本地内核不保证取消原生在途业务；状态未知时先核对原会话/轮次及发送记录。

恢复步骤：

1. 在Web看原项目/任务/消息/角色绑定，记录原operationId、CID和已持久的turn ID。
2. 在原Harness查看同一会话，或用支持的只读历史查询检查精确原轮。无stop/可信终态时保持待核对，不能用idle或进程已退出释放未知。
3. 有合法证据时由维护者走对应产品核对入口；当前受支持的恢复范围有限，不提供任意用户上传终态证明或“强制清未知”。不要直接改业务SQLite、删租约、新建替代会话或重发原请求。
4. 新任务需新的有效授权和当前能力；用户暂停、预算和权限保留，角色无权自己解除。

对话正文、产物和任务状态是不同事实：看到助手回复不证明任务已验收；有产物不证明测试通过；有测试报告不代替独立复核。主负责人最终应汇总实际结果和未完成项。

维护或卸载时仅移除明确属于本安装的程序文件。项目、数据、官方历史、未知来源文件必须保留。提交问题前脱敏凭据、配对码、用户路径和真实聊天；私密漏洞报告入口尚未实际启用，不应公开上传敏感复现材料。


alpha.2更新：已测试版本及能力记录仅供参考，不按版本或历史哈希阻止接入；实际接口错误如实报告。运行中程序被替换需正常重启。
