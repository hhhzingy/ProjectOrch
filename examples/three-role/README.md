# 最小三角色示例：文本规范化工具

本示例是用户目标模板，不包含真实会话或验收结果。运行前需已验证本机官方Harness身份及有效模型输入预算；当前公开预备包默认不放行原生。

1. 创建新的空项目目录，例如E:\OrchExample。Web建项目选三角色并确认职责/路径/预算，把生成指令交给控制Harness；不重复bootstrap，保存实际operationId，ready后再发业务目标。
2. 在控制Harness说明：

> 请使用ProjectOrch管理本项目，由受管负责人规划两个大批次：ZCode实现normalizeLines(text)及Node测试/报告，Codex独立复核。函数按CRLF/LF分行、trim、去空行、区分大小写去重并保持首次顺序，返回数组。独立复核必须看真实文件和测试结果；有错误退回同会话修复。复核者自己的复核记录任务依赖执行报告可用，不依赖执行任务已验收。你当前Codex只读，结论保存持久summary和裁决，可引用实际核对的原报告，不冒称自写文件。先读取当前Schema/权限/版本；任务执行read→claim→read，再产出/问答/提交。不扩权、预算或解除暂停；unknown保存断点，不重发。

3. 在Web观察角色和任务；指定用户问题由用户答复，业务答案不是原生权限审批。执行者用真实artifactId/version/sha256/byteSize登记具名输出，独立角色实际核对后按指定ruleId裁决。
4. 最终检查实际文件、Node测试结果、独立结论和遗留问题。创建/发送成功不是业务完成；若缺可信终态就报告待核对。

不要在示例里填用户认证、真实聊天、个人目录或原生会话ID；不要用修改数据库或复制历史到新会话来“恢复”。
